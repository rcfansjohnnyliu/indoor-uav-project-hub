## 1. 本阶段交付

**已有前置能力：** 用户确认七寸机搭载 MicoAir743 V2、PX4 1.15.4、MTF-01P 光流/测距及图示硬件，已能稳定定点悬停和飞行。详见[硬件与飞行基线](../docs/09-seven-inch-hardware-baseline.md)。不再将“从零实现基础悬停”作为主要研发工作包；优先补齐机载电脑的人体感知、相对测距、平滑参考、飞控指令接口和闭环反馈。原有姿态/定位稳定控制由 PX4 负责。该能力来源为用户确认，不冒充本轮独立实测，也不扩大实机输出权限。

限定室内条件下，七寸 RK3588 平台重复完成指定人员跟随、平滑运动、主动改善观察、普通障碍绕行、遮挡与身份模糊处置、自主判断下方降落区域及条件满足时降落，并采集可追溯、有尺度的三维人体骨架。正常过程不依赖反复人工纠正。

骨架关节精度暂不设交付门槛，但尺度、时间、坐标、有效性和跟飞距离仍必须有依据。先做采集与软件闭环，再做受控飞行；前者通过不能宣告整阶段完成。玻璃、密集人群、突然闯入单列扩展验收，未通过的场景仍为未覆盖，不能由普通场景通过推定。3.5 寸、RK3576、室外通用另阶段管理。

## 2. 技术路线取舍

| 模块 | 本轮规划选择 | 定型前的否决/退出条件 |
|---|---|---|
| 骨架感知 | 先验证 Rockchip YOLOv8n-Pose；保留检测器＋RTMPose | 固定模型/commit/权重与后处理；精度、完整链路负载或许可不适用则转备选，不预承诺最快 |
| 身份 | 先把现有身份状态机接入真实观测；按缺陷证据触发 ByteTrack、BoT-SORT 无/有 ReID 对比 | Track ID 不等于指定身份；基线也须跑同衣交叉、遮挡及拒绝恢复测试；失败后进入同输入比较，不能省略所选方案的验证 |
| 米制骨架与躯干距离 | 同步双目＋OpenCV 几何为优先实验路线 | 左右串人、不同步、尺度/标定错误、重投影或正深度失败须无效；硬件尚未定型 |
| 目标估计和平滑 | 在现有模型上评估 KF/EKF 等状态估计，独立做米制轨迹约束 | 测跟随误差、超调、jerk、滞后与恢复跳变；不把感知频率高于 PX4 内环作为目标 |
| 环境与规划 | 先复核既有接口；StereoSGBM 作深度实验基线，EGO 系列作方法比较 | 无深度不等于自由空间；盲区不能获通行许可；整机尺寸、制动空间和时效检查必须闭合 |
| 主动观察 | 在可观测且可达的有限空间内比较视角收益 | 无改善位置时允许退化；搜索必须有边界与切换抑制，不能无限左右试探 |
| 降落 | 独立区域感知、许可与下降监测工作包 | 仅测高、没检测到人、等待超时，都不能单独批准下降 |
| 开源复用 | 薄适配层＋不可变来源清单，最小修改现有模块 | 网球工程不整体移植；单目根相对 world landmarks 不直接替代相机距离；归档 PX4-Avoidance 不作直接生产基线 |

开源结论采用用户附件的条件性审查；本轮未重新联网逐源验证。P01 必须锁定官方 commit、权重 hash、导出脚本、SDK/驱动、许可证。框架包装层的许可不能代替模型/上游来源许可。性能与闭环是否合格由实验裁决，文字复核不替代实测。

PX4 实机版本已由本次图片明确为 **1.15.4**。参考材料中的 1.16 文档在接口落地前必须按 1.15.4 复核；不因开源示例版本不同自动升级现有稳定平台。UART1/3/4 在图片中已有数传/GPS/光流用途，机载电脑端口尚待确认。

## 3. 两个月功能原型目标与双周交付

## 4. 可执行工作包提案

实现类工作包均须在 Product `/srv/indoor-uav-product` 的获准 allowlist 内落地，不能在本资料库实现飞行产品。以下新增模块名均为建议位置，正式契约前按现有模块边界确认。每个编号可按文件范围拆成单次会话可验证的小任务；对应测试和工程证据与实现一起交付。

### P00 基线、数值和既有任务范围对齐

- 依赖：本轮附件与只读审查。映射 HGAF-T03～T11、M6-T03/T04、M7-T01～T05；新需求无覆盖处再提议新任务。负责人角色：需求/系统工程。
- 交付位置：需求差异表、验收矩阵及正式 PRD 更新提案；冻结快照不直接编辑。
- 判据：REQ-01～14 均有模块、场景、判据、证据层级和任务映射；旧任务接受记录不被改写；三米定义等未决项有明确状态。
- 验证：逐项对照有效契约与台账，审阅覆盖差异；不将 READY 当可执行。

### P01 候选来源、许可与测试数据固定

- 依赖：P00。与 P02 可分别准备。负责人角色：视觉/部署。
- 交付：候选清单和许可记录、固定输入输出样例、按人员及录制场次分开的调参与保留测试集；建议落在获准 `tasks/product/` 与测试 fixture 范围。
- 判据：代码/权重/导出/SDK 全部可定位；每段数据有来源和标注；保留集不通过相邻帧泄漏到调参集。
- 验证：重建输入与模型来源清单，校验 hash；对照附件 G0，不把可变 main 分支当固定版本。

### P02 时间、坐标、有效性和覆盖契约

- 依赖：P00。负责人角色：系统/控制。
- 交付：扩展 camera、telemetry 与相关 contract tests；定义捕获时间、时钟映射、序列和真实观测有效期，以及相机/机体/导航变换、米与弧度、七类独立健康状态。
- 判据：身份可信、采集有效、三维有效、骨架可见性、定位健康、路径可通行、降落许可相互独立；时间倒退/重放明确拒绝；前向/侧后/下方观测缺口逐项列出。
- 验证：错单位、错坐标、错误外参、时间偏移、旧观测伪刷新反例；静止场景相同像素不能单独判定采集冻结。现有旧帧规则保留回归。

### P03 姿态检测适配与等价性

- 依赖：P01/P02。对应 M2 历史感知任务的修订/后继提案。负责人角色：视觉。
- 建议文件范围：detector 适配模块、pose 单测、模型对照 fixture、工程证据。
- 判据：框、分数、浮点关键点和关节置信度对齐；补边/裁剪/原图坐标只还原一次；低分候选保留而不自动升级为可信飞行观测。
- 验证：原模型/ONNX/RKNN 同图对照；不同宽高比、半身和坐姿样例。板端实际推理需适用板端任务权限，离线端先完成适配测试。

### P04 指定身份候选比较

- 依赖：P03。对应 HGAF-T03 的修订/后继。负责人角色：视觉。
- 建议文件范围：identity manager 的关联适配器、真实检测回放 fixture、测试与比较报告。
- 判据：基线先接真实输入并评估误跟/错恢复/拒绝率/恢复时间；若不满足已登记判据，启动 ByteTrack、BoT-SORT 无/有 ReID 的同输入对比并记录开关和模型；身份模糊必须拒绝继续跟随。备选实验不阻止已满足判据的基线演示，但失败基线不能获验收。
- 验证：同衣交叉、转身、坐起、桌后遮挡、出入画、变帧率；检查 ByteTrack 二次缩放和就地修改，确认上游缓冲区隔离。

### P05 双目躯干与米制骨架最小链路

- 依赖：P02/P03、P04 的目标身份输入契约及可用同步双目资料；几何开发可先使用明确标注身份的录制资料，不等待全部关联器比较，端到端验收仍须真实身份链通过。负责人角色：视觉几何。
- 建议文件范围：双目关联/三角化模块、缺测 contract、几何测试、证据；同步采集、标定与重建如跨多个子系统，分别拆分派发。
- 判据：左右是同一个人及同名关节；尺度/单位/标定来源可追溯；真实观测/预测/补全/缺测分别记录，躯干距离不能依赖手脚位置。
- 验证：不同步、左右串人、零/小视差、正深度、极线和重投影误差；关节精度暂不考核不代表米制尺度和控制距离免检。

### P06 自运动补偿与目标状态估计

- 依赖：P05 与带有效时间/自身速度位置语义的遥测输入。对应 HGAF-T04/M6-T02 扩展。负责人角色：控制/估计。
- 建议文件范围：target_state_estimator 扩展、变换适配、合成运动 fixture、focused tests 与证据。
- 判据：固定人/移动相机与移动人/固定相机可区分；预测有截止时刻和不确定性；坏自身状态或身份跳变不进入可信估计。
- 验证：KF/EKF 作为可比较候选，记录估计误差、滞后和创新异常；不得把现有几何不确定性边界描述为已标定协方差。

### P07 平滑米制跟随参考

- 依赖：P06。对应 HGAF-T05/T06/T07 的有范围扩展。负责人角色：控制。
- 建议拆分：躯干与距离策略；米制 v/a/jerk/yaw 约束；重捕获转换，各自带单测和回放证据。
- 判据：距离按正式定义评估；坐起/手脚动作不直接导致危险参考跃迁；速度/加速度/jerk/偏航与时延预算满足预先登记阈值。
- 验证：停走、转弯、参考点缺失/恢复、错误测距、延迟和抖动；比较滤波前后跟随误差及超调，不能只展示平滑曲线。

### P08 观测空间与普通障碍规划

- 依赖：P02 及真实/合成深度输入；P05 的标定可复用。对应 HGAF-T08 后继提案。负责人角色：规划。
- 建议拆分：障碍/未知空间 contract；整机净空与制动走廊检查；可行参考规划，每项限定 3～5 个核心文件后派发。
- 判据：前向深度只授权其覆盖且仍新鲜的运动空间；路径检查包含整机与安全余量；无路径/未知必须返回明确信息而非假装空闲。
- 验证：低纹理、细腿、通道不足、盲区、移动障碍和停止距离；规划器更换须证明现有模块不足，不能先整体迁移 ROS。

### P09 主动观察与不可改善退化

- 依赖：P04/P05/P08；米制运动接口依 P07。负责人角色：规划/视觉。
- 建议文件范围：观察策略、可见性 contract、两类场景 fixture、focused tests 与证据。
- 判据：有安全收益时主动改善视角；无可达好视角且头肩躯干可见时允许部分采集；切换抑制和有限搜索使其不反复左右试探。
- 验证：相同遮挡分别设置可改善/不可改善环境；暂停后人离开有效范围必须重新进入失效判断，不能永远沿用可跟随标志。

### P10 降落区域与异常处置

- 依赖：P02、下方感知覆盖方案；P08 可复用空间/占用语义。负责人角色：感知/安全控制。
- 建议拆分：降落区域感知；适合/不适合/未知许可；丢失/接管/定位/电量优先级状态机，各自带独立测试。
- 判据：雷达测高不单独批准降落；许可在下降中持续有效；无安全区域、定位退化、低电并发时的受限处置有定义，不能无限等待或无条件下降。
- 验证：空地、桌面/边缘、人员进入、区域不可见、许可过期和信息矛盾；无法满足安全前提时明确该场景未支持，不承诺任意故障必能安全落地。远处降落点搜索/返航不默认纳入。

### P11 数据归档与板端全负载

- 依赖：P02 可先设计归档；最终负载测试依 P03～P10 与 RK3588 环境。负责人角色：嵌入式/测试。
- 建议拆分：不可变观测记录；回放恢复；板端测量与故障注入，各自有受控输入和报告。
- 判据：左右图像时间、标定、二维/三维、身份、遥测、决策关联可回放；记录失败不阻塞控制；两路采集/姿态/ReID/深度/规划/编码并发时满足已登记预算。
- 验证：测尾延迟、队列、丢帧、温度/内存及连续运行；注入相机停止、推理停止、传输活跃但旧观测、磁盘慢/满，记录有效退出。真实采集与板端访问须获适用任务授权。

### P12 M6 治理与非解锁命令路径

- 依赖：先核对 M6-T02 接受证据、M6-T03 当前绑定和已有任务专属授权；模拟路径可在 P02 后准备，完整新能力覆盖依 P07/P10/P11。
- 正式任务：现有 M6-T03（CE0D48C62840-31）、其后 M6-T04；不新造重复任务。
- 判据：mock/录制路径的非法、过期、错坐标、未授权命令均拒绝，输出授权保持关闭；聚合新需求覆盖报告；M6-T04 修订与 HEAD 沿治理路径处理。
- 验证：契约指定 focused tests、`make verify`、`make safety-check` 和权限/证据审计。已有授权须检查是否覆盖修订后的输入与边界，不要求无理由重复授权，也不继承到新增飞行权限。

### P13 真实 PX4 动力学闭环仿真

- 依赖：完整验收依 P07～P12 核心接口/失效链，以及明确有效的仿真任务契约和专属权限。具备适用权限后可在 P02 和 P12 最小无输出接口确定时先准备/验证隔离仿真接入；早期注入目标必须标为合成输入，不能当真实视觉端到端通过。负责人角色：控制/验证。
- 建议文件范围：隔离仿真适配、场景配置、验证脚本和证据；现 HGAF-T10 为历史参考，不改变它的已限定边界。
- 判据：实际 PX4/动力学执行的版本、时钟、接口与场景可追溯；完整跟随/观察/障碍/降落行为及故障响应达到冻结判据；不能把 JSON 证据重放当动力学仿真。
- 验证：延迟、定位退化、身份错配、旧观测、无安全降落区；记录物理单位轨迹和参考/响应。仿真通过不转授实机权限。

### P14 七寸受控综合验收

- 依赖：P11/P12/P13 合格、M6-T04 就绪审查、M7 计划覆盖修订，以及明确实机 Human Authority/合格场地/安全员。
- 顺序：复用用户已验证的定位飞行基线并核对新增链路影响/接管 → 观察式数据验证 → 受限指令/单轴 → 单人跟随 → 普通障碍及主动观察 → 遮挡/失效/降落 → 限定多人综合；玻璃等另场景验收。稳定定位模式不能替代新机载指令模式的切换、失联与控制响应验证。
- 判据：预先约定重复次数、有效任务时长、正常跟随误差及暂停规则；14 项需求逐项有证据；必须接管避碰的该次不计自主通过。
- 验证：冻结版本、同步录像/遥测/感知/状态日志、逐次结果与失败样本；仅经批准的物理试验流程执行。未支持场景明确保留，不静默缩减范围。

## 5. 检查点与停止规则

- C0（P00～P02）：审查需求冲突、覆盖和数据责任；版本/许可/关键安全语义缺失时不锁定生产依赖。
- C1（P03～P07）：身份、双目和米制链路可复现；错误身份/无效距离获可信标志即阻止晋级。硬件未就绪可继续不依赖它的离线实现。
- C2（P08～P10）：可通行/未知、可改善/不可改善、可降落/不可降落/未知及冲突异常有明确行为。
- C3（P11～P13）：整链路负载与真实仿真均通过，才提交实机就绪审查；服务恢复并不替代这些产品证据。
- C4（P14）：限定场景重复自主成功后，才声明七寸对应范围通过。REQ 数量不是等权工程量，不用代码提交数计算完成率。

## 6. 当前需先收敛的四组输入

1. **距离与人体动作**：三米以哪个点为参考，水平还是空间距离；±0.5 米适用的正常跟随状态、避障/暂停例外及恢复判据；坐起/躺卧时的高度规则。上午数值保持来源，正式含义不能猜。
2. **感知覆盖与配置**：双目型号/同步/基线/视场、固定安装外参、侧后方可达范围、下方区域感知来源、可用 FCU 速度位置及固件。可以先出要求和验证方案，不能冒充已经采购。
3. **失效与不能降落**：短时预测、身份确认、等待截止、接管优先级、定位/电量阈值，以及下方未知/不安全时的处置范围。
4. **验收集合与运行预算**：普通室内场景几何、上午约 10 人与 3～5 分钟如何分配到分项/综合测试、重复次数、成功标准和完整链路延迟预算。复杂场景分别登记。

双目具体算法参数、KF 噪声矩阵、ReID 阈值和轨迹权重可以后续标定，但测试通过门槛必须在评估前登记，不能看结果后降低。完整三维骨架精度优化、小型化和室外扩展可后置，不后置本阶段身份/测距有效性或降落判断。
