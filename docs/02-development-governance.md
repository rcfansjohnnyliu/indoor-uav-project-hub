# 研发管理流程

1. **需求与基线**：从经批准的 PRD、架构决策和安全要求建立任务；记录版本、来源与负责人。
2. **任务排期**：在 Dashi 维护任务、依赖、状态和人工门禁；执行前检查前置条件、有效契约、预算和安全绑定。
3. **实施与验证**：Product 代码只在 NUC `/srv/indoor-uav-product` 修改；保留测试、日志、证据哈希与不可变 HEAD。
4. **验收与投影**：符合 `AUTO_ACCEPT_ELIGIBLE` 的软件 PASS 可形成本地权威验收，并投影到 Dashi `in_review` / `等待确认`；Dashi `DONE` 由人工审计。
5. **受阻与升级**：失败按受控重试预算进入 `FAILED -> BLOCKED -> REFUSED`；BLOCKED 应同步到 Dashi，不得绕开阻断。
6. **发布与回顾**：每次阶段交付记录版本、验证结果、剩余风险和下一门禁。日报只汇总事实，不改变任务权威状态。

## 权限边界

Control Plane 仓库只保存编排资料。正常 Product 自动化使用 SSH 别名 `vision-nuc-codex` 和 `uav_codex` 身份。冻结的 uavctl 0.1.3 不修改。硬件、HIL、真实飞行、arming、执行器输出及带硬件权限的任务必须等待明确 Human Authority。

## 展示字段

每条进度至少记录：任务 ID、所属阶段、权威状态、本地验收状态、最后核验时间、来源链接或提交、验证范围、阻断事项、下一动作。显示层遇到来源冲突或无法查询时写“待复核”，不推断为通过。
